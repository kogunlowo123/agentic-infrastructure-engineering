# Runbook: Cost Optimization

## Overview

This runbook guides platform operators through reviewing and acting on cost
optimization recommendations generated by the cost-optimizer agent.

## Prerequisites

- Access to GCP Billing via IAM role `billing.viewer`
- `gcloud` CLI authenticated
- API access to the platform

## Step 1: Retrieve Cost Forecast

```bash
curl -X GET "https://api.agentic-infra.example.com/api/v1/cost/forecast?project_id=<PROJECT_ID>&days=30" \
  -H "Authorization: Bearer <TOKEN>"
```

Review the response:
- `current_monthly_usd`: Actual spend extrapolated to monthly
- `projected_monthly_usd`: Projected spend if trends continue
- `estimated_savings_usd`: Potential savings from recommendations
- `recommendations`: List of specific actions

## Step 2: Review Recommendations

Each recommendation contains:
- `resource_id`: GCP resource or service name
- `recommendation`: Human-readable action
- `estimated_savings_usd`: Expected monthly savings
- `priority`: high/medium/low

**Common recommendations:**

### Compute Engine rightsizing
Recommendation: downgrade instance type from `n2-standard-8` to `n2-standard-4`
```bash
gcloud compute instances stop <INSTANCE_NAME> --zone=<ZONE>
gcloud compute instances set-machine-type <INSTANCE_NAME> \
  --machine-type n2-standard-4 --zone=<ZONE>
gcloud compute instances start <INSTANCE_NAME> --zone=<ZONE>
```

### GKE node pool rightsizing
Recommendation: reduce max nodes in autoscaler
```bash
# Edit infra/gcp/gke/main.tf
# Reduce max_node_count in node_pool autoscaling block
# Submit PR for Terraform apply
```

### Cloud Storage storage class
Recommendation: migrate infrequently-accessed objects to Nearline/Coldline
```bash
gcloud storage buckets update gs://<BUCKET> \
  --default-storage-class=NEARLINE
```

## Step 3: Implement Changes

1. For infrastructure changes: create Terraform PR, get T2 approval, apply via CI/CD
2. For non-Terraform changes (storage class, etc.): apply via gcloud or console
3. Document all changes in the audit log

## Step 4: Verify Savings

After 7 days, re-run the cost forecast and compare:
- `estimated_savings_usd` in new report should reflect implemented optimizations
- Review GCP Billing dashboard for actuals

## Escalation

If LLM costs exceed budget threshold (80%):
1. Review `GET /api/v1/cost/forecast` for per-tenant spend
2. Check `platform/gateway/` budget enforcer logs
3. Consider reducing `token_budget.max_total_tokens_per_session` in agent registry
4. Contact platform team to review rate limits
